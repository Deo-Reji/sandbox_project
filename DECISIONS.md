# DECISIONS.md

Decisions not covered by the brief, with the reason. Newest at the bottom.

1. **Pyodide 0.28.3 pinned** (`https://cdn.jsdelivr.net/pyodide/v0.28.3/full/`). Ships pandas 2.3.1 / numpy 2.2.5. The only CDN dependency; everything else is vendored.
2. **No Faker.** `data/generate.py` uses only the standard library with a fixed seed, so anyone can regenerate the data with a bare Python install.
3. **Expected outputs are generated by `data/build_expected.py`** using CPython's `sqlite3` (same SQLite dialect as sql.js) and local pandas. The Playwright harness then re‑runs every solution through the real browser engines and asserts PASS, so Python‑side and browser‑side results must agree. Excel expected values come from a pandas "oracle" expression per problem, so the HyperFormula formula is cross‑checked against an independent computation.
4. **ER diagrams are a tiny home‑grown SVG renderer** (`js/ui/erd.js`) driven by PRAGMA output, used both for the dataset schema drawer and for the "what you built" view on the Database Design tab. Mermaid would add ~2 MB of vendored JS for a single diagram.
5. **HyperFormula function policy**: only functions present in `HyperFormula.getRegisteredFunctionNames()` for 3.5.0 are taught or tested. Notable absences that shaped the Excel problems: no `CONCAT` (use `CONCATENATE` or `&`), no `AVERAGEIFS` (use `SUMIFS/COUNTIFS`), no `LET`, no `RANK`. `XLOOKUP`, `FILTER`, `UNIQUE`, `SORT` exist but are left out of v1 as the brief asked.
6. **Pandas I/O blocking is best‑effort**: in the worker, `open` is replaced, and `socket`, `urllib`, `http`, `requests`, `pyodide.http`, `js`, `subprocess`, `pathlib` file ops are poisoned via `sys.modules`. It is a browser sandbox on the user's own machine, so this exists to keep problems honest, not as a security boundary.
7. **DB Design grading DSL**: hidden checks are JSON steps (`sql_ok`, `sql_fail`, `query_equals`, `fk_exists`, `columns_not_together`, `column_in_pk`, `unique_on`, …) evaluated against PRAGMA tables. Prompts name tables/columns only where the behavioural inserts need them.
8. **Hash routes**: `#<track>/<item>` where item is `tutorial`, `sandbox`, `easy-1 … hard-5`, or `challenge-N` for Exploration.
9. **Engines run in Web Workers.** SQL (sql.js) and Python (Pyodide) each live in a worker, so a runaway query or loop is cancelled by terminating the worker after 15 s and rebuilding it. The SQL database is rebuilt from the cached file bytes, which takes about 0.1 s. Pyodide reloads from the browser cache, which takes about 4 s.
10. **Graded SQL is read-only.** Only `SELECT`, `VALUES` and `WITH … SELECT` are accepted. The `REPLACE()` string function is allowed, but `REPLACE INTO` is not. The Sandbox allows anything, and Reset DB reloads the file.
11. **HyperFormula's `TRUE`/`FALSE` literals** are not recognised by default (they give `#NAME?`). The grid registers named expressions `TRUE = TRUE()` and `FALSE = FALSE()`, so `VLOOKUP(…, FALSE)` and `IFS(…, TRUE, …)` behave as they do in Excel.
12. **Excel problem changes forced by the engine:** no `CONCAT` (Easy 4 uses `CONCATENATE`), no `AVERAGEIFS` (Medium 1 uses `AVERAGEIF`), no `RANK` (no ranking problem), no spilled dynamic arrays (Hard 3 uses `LARGE(IF(...))`, which returns a single value). Every Excel target is computed by an independent pandas "oracle" and then matched by HyperFormula in the browser.
13. **Excel answers must be formulas.** A cell holding a typed value fails with "must contain a formula". The output pane shows each answer cell's value beside its target, as the brief requested. This reveals the targets, a deliberate trade-off for a practice tool.
14. **Exploration is SQL plus pandas only.** The Excel version of the data-quality challenges was cut from v1. The Exploration tutorial lists the Excel equivalents (`ISBLANK`, `TRIM`, `VALUE`, `IFERROR`), and they can be tried in the Excel sandbox. The workbook extract is clean data, so grading messy-data Excel work would need a second workbook.
15. **Exploration has 12 challenges, not 15.** The brief asked for "at least 10". The sidebar lists them as Challenge 1–12 with a difficulty tag rather than Easy/Med/Hard pills.
16. **Prompt examples show shape, not answers.** The example under each prompt shows the expected columns and at most 2 rows. When the whole result is 3 rows or fewer, the values are hidden.
17. **Database Design Hard 5 is the single multiple-choice item** (spot the 2NF violation). The other 14 are hands-on DDL graded by inserts and PRAGMA inspection. A problem names tables or columns only where its behavioural inserts need them.
18. **`section_number` and `room_number` are text** (`'01'`). The pandas loader pins them to `str` so SQL and pandas answers agree.
19. **Shifted rows in `students_raw`** keep `home_state` intact, because the shift starts at `home_city`. The ground-truth state counts therefore include them.
20. **CI regenerates the data and diffs the CSVs** to catch non-determinism. The `.sqlite` files are excluded from the diff because SQLite page layout can differ between library versions even when the data is identical.
21. **Local test artifacts go to the OS temp folder.** OneDrive locked Playwright trace files mid-write (EBUSY), which made the harness fail intermittently. CI still writes them to the repo root for upload. Suites are independent, so one failure no longer skips the rest.
